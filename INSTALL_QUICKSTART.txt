This file is a quickstart guide for using the Domain Access
suite of modules.

For full documentation, see INSTALL.txt and README.txt

INSTALLATION INSTRUCTIONS

1. Before proceeding, you must install and configure Backdrop
    without installing this module.

    Note that you only need one settings directory and file.

    Every domain you plan to use must already reach this Backdrop site:
    DNS, the web server (virtual host aliases) and the SSL certificate
    must cover all of them. Visiting each domain should show the same
    site. See INSTALL.txt, section 2.2.

2. Unpack the download and place it in your modules directory.

    Note the path to this directory, it is normally:

      'modules' or 'modules/contrib'

3. Add the following lines of code to the end of your settings.php file:

/**
 * Add the domain module setup routine.
 */
include BACKDROP_ROOT . '/modules/domain/settings.inc';

    This is the step most often missed. Without it, the module installs
    without complaint, but every domain behaves like the primary domain
    and administrators see "Domain access failed to load".

    NOTE: Change '/modules/domain/' to the path from step 2, for
    example '/modules/contrib/domain/'. A wrong path is the most common
    problem. See INSTALL.txt, section 4.4, for further help.

    IMPORTANT: These lines must come after the database settings
    ($database or $databases). If settings.php includes another file
    that sets the database (such as settings.local.php, or a file added
    by your host or local development tool), add these lines after
    that include. The very end of settings.php is normally the safe
    choice.

    NOTE: Domain Access must set $base_url itself. If something sets
    $base_url before these lines, add "unset($base_url);" just before
    the include. See INSTALL.txt, section 4.1.

    NOTE: By default, people log in on each domain separately. To share
    logins across subdomains of one domain, set $cookie_domain. See
    INSTALL.txt, section 4.3.

    NOTE: If you remove the module, or perform a Backdrop core major
    version upgrade, remove these lines from settings.php. See
    UPGRADE.txt for details.

4. Visit your primary domain, go to Admin > Functionality (Modules).
    There you will see the Domain module group. The primary domain is
    created from the domain you are visiting.

    Only enable the Domain Access module.

    Submit the configuration changes to your modules.

5. Rebuild content access permissions as instructed.

6. Configure permissions for the module, normally you will give your
    site administrators the following permissions:

    -- 'administer domains'
    -- 'set domain access'

    If you intend to use access control for editors, you may wish to set
    the following permissions:

    -- 'assign domain editors'
    -- 'edit domain content'

    For more information see README.txt.

    NOTE: Some of these permissions may be pre-configured for the
    site's administrative role.

7. Read the main README.txt file for the Domain Access module.

8. Go to Admin > Structure > Domain and configure the module.

9. Now you are ready to explore the options available to you.

    The Domain Access suite contains a number of optional helper
    modules.  You do not need to use any of these modules, but
    they may add desirable features.

    Each of the modules has its own INSTALL.txt and README.txt files.
    Please read them carefully before activating them.

----
USING BEE

When using Bee to enable the module, pass the URL of your primary domain
with --base-url (include the subdirectory, if any):

  bee en domain --base-url=https://example.com

Then rebuild node access tables and clear all caches:

  bee php-eval "node_access_rebuild();"
  bee cache-clear all

See INSTALL.txt, section 3.1.
